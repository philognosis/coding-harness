Six ideas hold it together.

01

Stateless agent, stateful repo

If it matters next week, it’s a file.

02

Context is a budget

Load a little always. The rest on demand.

03

Advice versus guarantee

Markdown is usually followed. Code always is.

04

Feedback beats instruction

A failing test teaches more than a paragraph.

05

The builder is not the reviewer

Fresh eyes carry no assumptions.

06

The repo is the teacher

Agents copy what they find.

The theory, now six ideas. The first five are unchanged from version 1. The sixth is new and comes from the talk: the codebase is one of the largest inputs an agent sees, so whatever is in it, good or bad, gets imitated.
