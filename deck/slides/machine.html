The talk draws a statechart after the fact so a reviewer can check the agent understood. Version 2 goes one step further: the state machine is the code. An Enum, one TRANSITIONS table and one transition function. Because the table is data, a script draws the diagram and four tests walk it, including a property-based test of random moves. You confirm the diagram in the new /model step, before any behaviour is written. Use a machine when something has three or more states and the order of moves matters, such as an agent run, a chat turn or a candidate pipeline. Plain request-and-response code needs only a typed function.
